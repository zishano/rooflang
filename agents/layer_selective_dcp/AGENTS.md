# Layer-selective DCP 与计算图联合优化任务

## 1. 任务与执行方式

在 RoofLang 中实现并自动搜索 decode 阶段的按层 Context Parallelism：每层 Attention 的 CP 度数从 `{1, C}` 中选择。`CP=1` 就是不对该层做上下文切分；不是跳过计算。交付正确、完整计费、可复现的实现及 Baseline / Selective DCP 对照实验。不要停留在设计建议，也不要把一次局部改善当作搜索完成。

这是独立任务入口，不继承 `agents/find_pareto_frontier/AGENTS.md` 的任务目标或修改白名单。仍须遵守当前会话授权、沙箱限制和适用的仓库指令。已有 Pareto agent 启动器的只读挂载不足以执行本任务；不要直接替换其提示词后假定具备写权限。应在独立工作副本的新 agent 会话中明确加载本文件，并给予下面列出的必要源码写权限。

没有额外用户参数时，采用以下默认值，并在实验 manifest 中记录：

- 模型：`dsv4_flash`；硬件：`h200`；GPU 数：64。
- 阶段：decode；主工作负载：`decode-64k`（seq_prefill=65536）；固定配置对照先用 PP=1、C=2、DP=32、EP=64、batch=64。先通过现有参数校验器确认合法，不得静默改配置。
- 扩展搜索：C 属于 `{2, 4, 8}`，PP=1，DP=64/C，EP=64；batch 属于 `{64, 128, 256, 512}`。保留 C=1、DP=64、EP=64 作为全局无 CP 参考。decode 的 batch 必须满足现有校验器要求的 `batch % (C * DP) == 0`；这里 C * DP=64，因此 batch 搜索保持原先的 1、2、4、8 倍最小合法 batch。
- 主指标与原始 Pareto agent 一致：`tokens_per_s_user_overlapped`（x）、`tokens_per_s_gpu_overlapped`（y）；要求 `memory_feasible_overlapped == true`。候选排序、剪枝上界、Pareto 前沿和性能验收统一使用 overlapped 口径。original/raw 与 elapsed 指标及其显存可行性仅作分别标注的补充，不能跨口径选最好值或替代主指标验收。
- 随机种子：0、1、2；每个固定外层配置最多评估 256 个唯一层策略（跨种子合计）。Baseline、测试和最终重跑不计入候选预算。参数可由用户覆盖，运行开始后不得为了美化结果修改。

本任务只要求静态、整次运行不变的层策略；不做逐 token 动态切换、prefill 策略搜索、任意中间 CP 度数搜索或模型架构变更。

## 2. 先检查并冻结基准

读取模型定义/配置/优化、`language/optimization/split.py`、通信融合、placement、simulator、实验搜索器和相关测试。重点检查当前 decode 的 Q 广播、KV 分片、输出 Reduce 的实际语义，以及稀疏索引选择规则。

记录起始代码版本与工作区差异；保留用户已有改动。保存将修改文件的快照和补丁。建立独立的带 run ID 的结果目录，不覆盖旧结果，不把旧记录当作当前实现的有效缓存。

在修改前运行相关测试和固定配置的原始 Baseline，保存完整日志、配置、错误和原始结果。当前全层统一 CP 是 legacy baseline。若发现既有语义或成本缺陷，保存其结果用于审计，但不能以此作为不公平的提速对手：修复后统一重跑 Baseline 和 Selective，DCP 机制归因使用相同正确语义及计费的 corrected baseline；与原始 agent 的性能验收另按第 6.C.1 节保留输入旧前沿比较。

## 3. 配置与实现契约

区分物理设备组大小 C 和每层 Attention 度数 `layer_cp[l]`。原全局 `cp` 与 DP/EP/PP 的分组约束不能因某层选择 1 而直接失效。

新增显式配置，例如 `layer_cp: tuple[int, ...]`，长度等于模型层数、使用 0-based 层号，各值只能是 1 或 C。缺省值等价于全 C，并保持旧调用兼容。序列化实际完整向量，不能只保存生成向量的启发式名称。

首版对 CP=1 层采用按请求分工的布局：在原 C 张卡组成的组内，按 batch 拆成 C 份，每卡独立计算其请求的 Attention，并持有这些请求在该层的完整上下文 KV。CP=C 层仍由同组各卡共同处理该组请求、按上下文切分 KV。

- 全局 batch 和请求集合保持不变。CP=1 层的局部请求分工不等于修改全局 DP 或 EP。
- 校验 batch、上下文以及其他相关维度的整除条件。无法表示的配置明确拒绝，不能截断、填造请求或省略工作。
- 所有相关算子必须一致处理请求归属：Q/KV 投影、Attention、索引缓存、KV 更新、输出投影、残差、MoE 接口与持久化依赖。不要只给 Attention split 添加一个 if。
- 按实际布局插入或消除 Scatter/Gather/AllToAll 等通信；在融合前后检查张量布局和请求顺序。不得无代价地改 shape 或 placement 来模拟重分布。
- 在固定策略中，各层的 KV 是各自的缓存。层间主要传递 activation，不能凭空加入“上一层 KV 搬到下一层”的迁移。
- 完整 KV 不必复制到每卡；按请求分片时总 KV 不应无故增加 C 倍。若以后探索单卡集中或完整复制，将其作为独立、明确计费的布局策略，不能混入首版搜索。

## 4. KV、迁移与显存成本

为每层记录布局描述：请求分片、上下文分片、实际 token 索引或可验证映射、dtype、大小、owner GPU、KV 与 index cache、副本数及生命周期。不要仅用 shape 作为布局证明。

显式区分三类成本：

1. 初始 KV preload、prefill→decode 布局转换：说明源布局和目标布局，计入对应阶段耗时及临时显存。若直接生成目标布局的合成缓存，标注其假设，不能宣称测得了真实转换收益。
2. 每步 decode：activation 重分布、Attention 集合通信、KV 新增/更新及必要的索引通信，均进入测量依赖图。
3. 常驻与瞬时内存：每卡 KV、权重、activation、通信 buffer、迁移期间新旧布局共存的峰值。报告实际峰值及现有并发投影口径的可行性。

检查 `record_memory_footprint` 元数据与模拟器实际分配/释放的区别；只添加 footprint 标签不一定计入真实峰值，不得据此宣称已完整建模。避免同一缓存双重计费，或把实际副本错误去重。峰值按每张 GPU 检查，不能仅检查总容量或平均值。

单步计时范围外的 preload、转换、post-output 必须单独报告；提供包含转换成本的多步摊销估算及明确公式。不得把每步必要工作移到测量边界外获得虚假加速。

## 5. 正确性门槛：先验证再搜索

结构合法、shape 一致、FLOPs 守恒都不能单独证明数值等价。建立小规模 CPU 数值 oracle，对未分片计算与实际转换规则对应的分片执行做比较；oracle 必须使用实际拆分的布局、mask 和索引语义，不能只验证一个与实现无关的教科书公式。

Attention 按 KV 分片时不能直接求和或平均各分片独立 softmax 后的输出。为局部输出与归一化统计量定义数值稳定的合并：例如使用局部 log-sum-exp 做正确加权。检查已有 Reduce 是否足以表达该语义；若不足，最小化扩展 IR/算子及其 FLOPs、通信字节和临时存储计费，不能只改注释。

稀疏 Attention 的全局选择必须保持一致，不能未经证明把全局 top-k 替换成每卡 top-k/C。若 DSL 仅描述工作量而无法承载所需精确语义，明确建模限制并修复必要表达；未解决时报告 `BLOCKED_CORRECTNESS`，不得把性能结果作为已验证优化。

至少覆盖：

- 全 C、全 1、交替层、单层关闭、连续区段关闭；跨层 activation 及残差顺序。
- C=1 退化行为，以及 C=2/4 的有效小规模案例；不同 batch、上下文和压缩类型。
- 稀疏选择、窗口、mask、索引映射、不均匀 logits、极端数值，以及不同分片贡献严重不均衡的情况。
- 初始缓存与多步 KV 更新；验证下一步仍使用正确请求的历史 KV。
- 非法策略长度/值/整除条件；重复或遗漏 KV；每卡内存、通信字节与小规模手算结果。
- 全 C 与旧路径的兼容性；必要的公共算子变化还须回归 prefill 和其他使用者。

固定随机种子；按 dtype 在测试前定义并记录 atol/rtol，输出最大绝对和相对误差，不为通过失败案例放宽阈值。复用现有测试基础，补充有意义的数值及成本测试。

## 6. 自动搜索流程

先实现参数贯通、合法性校验、结果记录、恢复去重和最小正确性验证，再开展性能搜索。搜索不要求人工指定最优层集合。

### A. 固定外层配置的配对对照

先在默认固定配置比较全 C Baseline 和若干 Selective 策略。除层策略及其必需的布局/通信外，模型、硬件、batch、DP/EP/PP、测量边界和计费完全一致。展示每层 Attention、通信、迁移和 HBM 差异，验证预期机制。

### B. 候选生成与预算分配

对每个合法外层配置使用确定性的候选生成器和独立随机状态：

1. 种子候选：全 C、全 1、交替层、按压缩比例/有效 KV 长度分组、按估计通信收益阈值选择。启发式只用于提出候选，不能替代仿真。
2. 单层消融：从全 C 起逐层关闭 CP，估计敏感性。不能假设层收益可相加，布局边界与峰值内存可能产生交互。
3. 保留最多 8 个可行非支配或接近前沿的候选，做单 bit、相邻区段和双 bit 修改；按稳定的指标排序与策略 ID 打破并列，避免无定义的选择顺序。
4. 当一轮邻域不改善时，用剩余预算作随机重启；三个种子共享去重缓存，各自记录来源。为随机探索保留至少 20% 候选预算。

缓存键必须包含模型、硬件、工作负载、GPU 数、batch、C/DP/EP/PP、完整 layer_cp、KV 布局策略、代码/配置摘要和计费版本。结果写入使用可恢复的原始 JSONL；失败、非法、OOM 也要记录原因，不能当成成功或从覆盖报告中消失。

不允许用“某个 mask OOM”推断其他 mask 或更大 batch 必然 OOM，除非给出适用的单调性证明。仅用可信的乐观上界剪枝，并在小层数问题上对照穷举，检查候选生成、去重、Pareto 和恢复逻辑。

### C. 外层搜索与最终对照

在第 1 节默认外层域内，为全 C Baseline 和 Selective 使用相同的合法配置集合。固定配置收益与允许改变 batch/C 的前沿收益分开报告。全 1 层策略与全局 C=1 参考也分开标注，不假定其外围图和放置天然一致。

固定 model 后按 `(workload, hardware, n_gpus)` 分组，以 overlapped 的两项吞吐形成 Pareto 前沿，只保留 `memory_feasible_overlapped == true` 的成功记录。优势判定使用未舍入值。不得用较低延迟但吞吐退化的点笼统宣称全面改善。

在同一最终代码状态、独立新进程中重跑 Baseline 和最终候选。重复确定性仿真用于复现确认，不把仿真确定性冒充硬件统计置信度。保存所有最优层向量与逐层成本，必要时输出 trace 检查通信边界。

### C.1 与原始 Pareto agent 一致的性能验收

读取 `/workspace/results/raw_results.jsonl` 中目标模型/组的全部输入记录（含 OOM、错误），冻结输入摘要并独立重建旧前沿，不覆盖输入。模型身份若未写入记录，须从来源配置验证，不能仅凭目录名假定。其他 workload、hardware 或 n_gpus 的记录只作参考，不参与本组验收。

- `F_old`：由输入记录中符合本组条件、成功且 overlapped 显存可行的点独立重建的前沿。
- `F_final`：最终代码状态下，新进程完整重跑验收域所得的可行前沿；不能直接混入未重跑的旧点来实现覆盖。
- `F_union`：`F_old` 与 `F_final` 合集的前沿。

验收域包括本组全部输入 case identity，以及第 1 节搜索域和发现的合法新增候选。即使输入包含该搜索域以外的 batch、C 或 PP，也必须保留并重跑其原始配置作为兼容性/前沿覆盖验证，不能静默过滤；这不扩大 DCP 层策略搜索域。不支持的输入配置须明确报告为未完成，不能以缩小旧前沿通过验收。

支配指两项吞吐均不差且至少一项严格更好；弱支配允许两项均相等。对同时属于 `F_final` 与 `F_union` 的点 n，定义 `D(n)` 为 `F_old` 中已不在 `F_union` 且被 n 弱支配的所有旧点。只有 `D(n)` 非空，且对其中每个旧点 o 至少满足以下一项，n 才是显著改善点：

- `(n.x - o.x) / o.x >= 0.05`
- `(n.y - o.y) / o.y >= 0.05`

只有本组每个 `F_old` 点均被 `F_final` 中某点弱支配，且至少存在一个显著改善点，性能验收才通过。不得先舍入或以容差凑满 5%。分母为零时明确报告并使用预先记录的绝对值检查；输入缺失或旧前沿为空不能当作自动通过。

若发现旧语义/成本缺陷，保留原始 `F_old` 的独立比较，同时在相同修正下重跑 corrected baseline 和所有候选，额外报告 corrected 前沿比较。不得悄悄用 corrected baseline 替换输入 `F_old`；最终 `IMPROVED` 须通过上述原始前沿验收，且在正确计费的 corrected 对照下仍满足相同的完整覆盖及显著改善条件。未完成任一必要验证时报告缺口，不能宣称已对齐验收通过。

### D. 计算图与层策略联合搜索

除按层 CP 外，自主探索语义等价的计算图与放置优化。保持 model、workload、hardware、n_gpus 及第 1 节的 C/batch 域不变，PP 仍为 1。

先通过 trace 定位瓶颈，记录每项假设的机制、乐观收益上界、修改、验证案例和保留/拒绝原因。至少调查：

- 图优化 pass 的组合、顺序、应用范围，以及合法融合与拆分。
- 请求/KV/activation 的设备与内存放置、布局及重分布路径。
- 通信融合、分组、顺序和冗余重分布消除，保留真实依赖和完整通信计费。
- 中间张量生命周期、buffer 复用与峰值内存，不得提前释放仍被使用的数据。
- 现有 runtime 能忠实表达的调度与计算/通信重叠，不得引入无依据的理想重叠。

先筛选图方案，再搜索其与 layer_cp 的交互。用完整、可序列化的 `graph_strategy` 记录 pass 开关/顺序、布局、放置、通信和调度参数；将其加入缓存键、候选记录和复现配置。原图与优化图必须能在同一最终代码状态下切换，不依赖手动切换补丁。

第 6.B 的原图层策略预算保持不变。另外每个外层配置最多评估 256 个唯一 `(graph_strategy, layer_cp)` 联合候选，跨种子合计、包含图方案筛选；失败/OOM 计入预算，测试和最终重跑除外。至少 20% 联合预算用于随机探索。记录未覆盖方向，不宣称全局最优。

最终在相同外层配置重跑四组消融：corrected baseline（原图、全 C）、仅 DCP（原图、选择层策略）、仅图优化（优化图、全 C）、联合优化（优化图、选择层策略）。公共正确性/计费修复一致应用于四组。分别报告 DCP、图优化与联合收益；纯 DCP 对照仍保持图方案一致。不能把纯图优化收益归因为 DCP。

## 7. 修改范围与实验纪律

允许修改选定模型的 `optimization.py`、`programs/experiments/` 和相关测试。可主动改进合法图变换、pass 组合、设备/内存放置、布局及通信调度，不限于逐层 CP 开关。

公共 `language/optimization/`、`language/kernels/`、`language/placement.py`、`language/graph.py`、`language/tensor.py` 和 `runtime/` 允许为 DCP 或有瓶颈分析支持的语义等价图优化作必要扩展。每项扩展须有明确机制、配置开关或兼容的旧默认行为、数值/依赖/成本验证及其他调用者的回归测试。成本模型变更仅用于修复可证明的表达/计费缺陷，对所有对照组一致应用；不得为了提高性能分数改变计费公式。

不得修改其他模型、模型定义/配置、硬件定义、preset 或验收规则。不得删除或放宽测试断言来掩盖错误。新脚本放在 `programs/experiments/`，新文档和实验产物放在 `/workspace/artifacts`。运行前检查允许路径在独立副本中可写，不修改宿主原始源码。

不改变模型架构、权重语义、精度、实际 token/请求数、硬件预设、通信带宽、指标定义或内存可行性阈值。不为了提高分数删通信、删 KV 更新、绕依赖、重复计算少算成本、改变计时边界或引入无依据的理想重叠。

保留旧 CLI 默认行为。文档中明确新 CLI 参数和可复制命令。不要提交、推送或覆盖用户改动。实验进程保持监督，检查失败和停滞；需要结束会话时先停止并记录未完成进程，不能把仍在运行的验证标记完成。

## 8. 停止条件与交付

所有正确性门槛通过后，当每个外层配置的原图层策略预算与联合搜索预算均耗尽，或对应有限合法候选域已穷举，结束该轮搜索；同时必须完成最终配对重跑及第 6.C.1 节的全验收域重跑。可提前结束邻域搜索但用剩余随机预算验证停滞。不要要求无法证明的“全局理论最优”，也不能把预算耗尽说成最优证明。

在结果目录交付：

- `manifest.json`：输入、版本/补丁摘要、指标、种子、预算、布局与计时假设。
- `baseline.jsonl`、`selective.jsonl`：完整配置、层向量、状态、原始指标、内存可行性、耗时与错误。
- `best_configs.json`：各前沿候选的可直接复现配置及 baseline 对照身份。
- `comparison.csv`：配对收益、前沿、显存、迁移与通信成本；分开呈现不同吞吐口径。
- `validation.md`：测试命令与结果、数值误差、成本核验、限制。
- `search_history.jsonl`：候选来源、父策略、种子、去重/剪枝理由及搜索覆盖。
- `report.md`：设计、搜索范围与未覆盖范围、最优发现、失败假设和下一步；明确这些是 RoofLang 仿真结果。
- 一键重跑入口：支持固定配置复现和完整预算搜索，支持中断恢复，不能依赖隐藏会话状态。

最终状态使用 `IMPROVED`、`NO_GAIN`、`BLOCKED_CORRECTNESS` 或 `INCOMPLETE`。仅在正确性门槛、全验收域重跑和第 6.C.1 节的完整前沿覆盖及 5% 显著改善规则全部通过时报告 `IMPROVED`。报告 `F_old`、`F_final`、`F_union`、每个显著点的完整 `D(n)`、两项未舍入增幅和未覆盖旧点。联合优化也可满足该条件，但必须通过四组消融注明收益来源；若仅图优化有效而 DCP 无增益，明确报告。新增权衡点或局部提升不足以通过验收。

验证完整但性能验收未通过时（包括只有局部收益）仍可保留正确、兼容、经测试的按层配置与搜索能力，并诚实报告 `NO_GAIN`。正确性未通过或实验未完成时，明确缺口，不编造收益，也不自动回滚用户既有工作。
