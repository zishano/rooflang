## 开发注意事项

- 先完成候选动作卡与成本推导，再增加动作；初版只开放 2～3 个经过验证的动作。
- 区分计划、已实现能力和已有证据。每个结果绑定配置、代码版本、动作和计时边界。
- 评价器、模型、硬件和合法性约束不交给 Agent 自由修改。
- 当前仓库 Agent 默认优化 `overlapped` 且禁止非默认 stream；新原型使用独立任务配置，不能直接继承为新方案的验收规则。
- 模型语义、精度、硬件保持不变；不使用删依赖、漏通信、改读取比例或改评分器制造收益。
- 本目录是设计与开发入口，不表示新的 TP 策略、完整闭环或 H100 后端已经实现。
