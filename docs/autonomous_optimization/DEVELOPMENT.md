## 第二至第五周

- 第 2 周：实现计划解析、确定性动作应用、合法性检查、仿真调用、日志回放和反馈迭代；接入一个 Agent 提供者。
- 第 3 周：将主攻动作接入完整43层，保留真实上游依赖；冻结动作集合，开展匹配范围的H100小实验。
- 第 4 周：强基线、规则、随机、AI同预算对照；消融、held-out、失败和OOM档案。
- 第 5 周：冻结功能，修关键问题，完成复现包、报告与答辩；必须形成可验收版本。
- 第 6～7 周：优先补最关键证据，核心任务通过后才开展存算网探索。

## 开发约定

1. 每次开发前确认当前分支为 `rooflang_dev1` 并检查工作区；不覆盖本地实验记录。
2. 一次提交围绕一个可审查的动作、验证或文档更新；明确实现了什么、验证了什么、哪些仍待完成。
3. 正式模块落点在闭环接口收敛后确定；方案中的 `contracts.py`、`actions.py` 等是建议职责，不表示已存在实现。
4. 候选动作修改执行计划，评价器与冻结输入独立；同一输入和动作应可回放。
5. 源码变更执行相关检查；文档变更检查链接和一致性，不因编辑计划重跑全部搜索。
6. 原始实验输出与正式验收证据分开管理，提交明确选择的文件，不批量加入 `.venv`、缓存和大型结果目录。
7. 若机制上限不足，不删除必要工作来追指标；记录失败原因和路线调整。
