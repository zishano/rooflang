# 候选动作与实验协议模板

本文件是设计模板，不是已经生效的数值阈值或可执行的动作 schema。

## 一、候选动作卡

| 字段 | 需要填写的内容 |
|---|---|
| ID / 状态 | 唯一编号；假设、待实现、待验证、接受或拒绝 |
| 目标算子/子图 | 精确节点标识、输入/权重/输出形状和dtype；关键路径占比 |
| 原始计划 | 每个张量的所有者、设备组、内存、stream及前后依赖 |
| 候选计划 | 分片维度、rank映射、内存/stream变化；完整的前后图 |
| 合法条件 | 维度和量化块对齐、可分性、归约/归一化规则、别名与副作用、输出恢复 |
| 必要通信 | Broadcast/Gather/Reduce/布局交换、源端读和目标写、打包与同步 |
| 代价差分 | FLOPs、权重/激活读取、每链路字节、缓冲大小与生命周期、峰值显存 |
| 收益假设 | 减少什么关键路径成本；新增代价；预计在哪些负载下成立或失败 |
| 验证 | 数值/结构检查、正例、无收益例、非法或容量例、完整模型对照 |
| 结果 | 实际指标、与预测的差异、是否保留、下一轮反馈 |

数学上的输出拼接不等于可以省略实际布局恢复；必须明确后继是否直接消费分片，否则通信需要计入。

## 二、正式评价协议

- 协议版本、冻结时间、确认人：待填。
- 模型、权重/定义哈希、精度/量化、硬件preset哈希：待填。
- 主工作负载及明确输入任务：待填；候选不得改变batch或历史长度获胜。
- 强基线与选择范围：待填；同任务、同硬件的既有最佳合法方案。
- 30%定义：建议 original 输出延迟降低率 `1 - T_candidate / T_baseline`；需明确是否为考核认可口径。
- 计时起止点、KV preload和post-output处理：待填并冻结。
- 数值正确性：参考实现、目标dtype路径、确定性/容差、logits/KV/输出检查；阈值需在候选结果之前确定。
- 显存与可行性：逐GPU容量、全部缓存/激活/通信缓冲、OOM及错误记录规则。
- 开发集、held-out：提前列出；不根据结果删除困难或OOM点。
- AI/规则/随机：相同动作集合和评估机会计数，明确非法提案是否计数；种子、LLM版本和费用另记。
- Pareto定义：单负载延迟—峰值HBM，或容量硬约束；跨batch曲线另列，不混淆指标。
- 终止规则：评估预算、连续无改进轮数、时间上限；不声称有限搜索证明全局最优。
- H100协议：同一真实硬件内比较；精度和软件版本相同，warm-up、同步、计时、重复测量及波动报告。

## 三、第一周路线评审记录

1. 已测瓶颈与不可消除工作量。
2. 候选能影响的关键路径比例及乐观收益上限。
3. 正例、失败例及新增计算/显存/通信代价。
4. 主攻选择和未选择其他方向的理由。
5. 主场景、动作集合、开发/验证负载和预算冻结情况。
6. 尚缺的证据及负责人/下一步；不能把计划勾选为完成。
